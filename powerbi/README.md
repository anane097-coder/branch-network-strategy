# Power BI — model, pages, and how to build it

Four pages, each answering stated questions rather than displaying everything
available. Build from `data/` (18 CSVs, 6.6 MB, regenerated by
`scripts/13_export_powerbi.py`) and `measures.dax`.

## Loading

1. **Get Data → Text/CSV**, load every file in `data/` except `_manifest.csv`.
2. In Power Query, set these to **Text** before load — they are identifiers,
   not numbers, and a leading zero lost here breaks every join downstream:
   `tract_geoid`, `county_fips`, `cbsa`, `uninumbr`, `cert`, `lei`,
   `service_type`, `is_main_office`.
   Illinois county FIPS begin `17` and Wisconsin `55`, so the damage is silent
   in this footprint — a tract GEOID typed as a number simply loses nothing
   visible and fails to join.
3. Paste the measures from `measures.dax`.
4. Create the five what-if parameters listed in §6 of that file.

## Model

Star, with `dim_tract` as the hub. Single-direction filters throughout;
nothing here needs bidirectional, and turning it on would make the market-share
denominator ambiguous.

```
dim_year ──< fact_branch_deposits >── dim_branch ──< bridge_branch_catchment >── dim_tract
                     │                     │                                        │
              dim_institution        branch_performance                             ├──< fact_index_components
                                                                                    ├──< fact_tract_competition
                                                                                    ├──< tract_capture_rate
                                                                                    ├──< unmet_demand
                                                                                    ├──< opportunity_index
                                                                                    └──< recommended_coverage
                                            fact_county_deposit_growth ──> dim_tract[county_fips]
```

`lmi_coverage` (3 rows), `recommended_sites` (6) and `ref_index_weights` (20)
sit disconnected and are read by measures directly. Connecting them would let a
page filter change a footprint-level constant.

## The four pages

### Page 1 — Market opportunity

Filled map of counties by `Selected Opportunity Score`; top-10 market table;
KPI cards for footprint deposits, `Deposit CAGR %`, `Market Share %`, branch
count. Slicers: state, CBSA, minimum market size.

The map should be coloured on the **size-adjusted** score. Nothing on this page
may rank on `Performance Index (raw, do not rank)`.

### Page 2 — Branch performance

Scatter of catchment potential against actual deposits with a fitted reference
line; underperformers fall visibly below it. Table ranked by
`Performance Index`. Drillthrough to page 3.

Filter to `service_type` 11 and 12. Drive-throughs and administrative offices
structurally book no deposits, so they score 0.0000 and sort to the top of the
review list — *"close the drive-through because it does not take deposits"* is
what this filter prevents reaching a slide.

### Page 3 — Branch detail

Single branch: deposit trend, catchment tract table, competitor branches within
radius, mortgage capture rate.

`fact_tract_competition` is **not** a catchment bridge. It counts competitor
branches near a tract and carries no branch identifier, because competitor
branches have no catchments in this project — their tract assignments were
never computed and their coordinates never validated. Do not build a
relationship from it to `dim_branch`.

### Page 4 — Recommendation and equity check

The page that carries the tension. Four things, together, above the fold:

| Element | Source |
|---|---|
| **The three sites** with supporting evidence | `recommended_sites` where `rule = "B_constrained"` |
| **The commercial set beside it** and what it cost | `rule = "A_commercial"`, `Selected Opportunity Score` |
| **LMI coverage before and after** | `LMI Coverage %`, `LMI Coverage % (recommended)` |
| **`Binding Test Result`** | measure |

The findings this page must state, not imply:

- The commercial set **fails** the binding test: non-LMI coverage grows
  **8.4×** faster than LMI. AC-06 as written would have passed it, because
  AC-06 tests that two numbers exist.
- The constraint costs **9.4%** of the unconstrained score.
- **Neither set places a branch in an LMI tract — 0 of 3 in both.** The
  constraint improves catchment composition; it does not site among LMI
  communities. It cannot: it selects from a shortlist that is 4.0% LMI against
  a 29.5% baseline, so **the ceiling is upstream in what the opportunity model
  surfaces, not in the constraint.** Read Rule B as a siting rule that avoids
  widening a gap — which is the only claim the evidence supports — not as a
  CRA response.
- One named risk, not three caveats: the shortlist concentrates in one
  Chicago-area growth corridor (29 of the top 50), and growth in that corridor
  is disproportionately cluster-estimated rather than observed (22 of 29
  against 9 of 21 elsewhere, phi +0.336). **One growth assumption, mostly
  estimated, in one corridor.**

Use `Shortlist Caveat` as a card beside the shortlist so the LMI share and the
estimated-growth share are read at the same moment as the sites.

### The what-if slider

Page 1 or 4. Five sliders over `Selected Opportunity Score`, with
`Rank Shift vs Published` on the same visual.

The slider is not there to show the ranking is robust — it isn't. Under a
growth-led weighting **39.7% of tracts move 500+ places and only 31 of the top
50 survive**. It is there to show the model is inspectable, and that the
weights were a judgement rather than a fact. Sensitivity, including which
component the shortlist actually hangs on, is in
[`../docs/sensitivity.md`](../docs/sensitivity.md).

## Refresh

`python scripts/13_export_powerbi.py`, then Refresh in Power BI. The export
verifies that the exported z-scores reproduce the published opportunity score
before writing, and refuses to write if they do not.
